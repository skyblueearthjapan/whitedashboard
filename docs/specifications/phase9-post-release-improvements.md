# Phase 9：初期リリース後の改善リスト（運用フィードバック反映）

（v0→v1へ育てるための改善バックログ）

## 1. このフェーズの目的

本フェーズの目的は、MVP（v0）を社内で使い始めた後に発生する
**「不便・不安・運用負荷・品質課題」を確実に回収して、v1へ段階的に育てる**ための改善項目を整理すること。

- 重要度（P0/P1/P2）で優先順位を明確化
- "作り込み"ではなく"運用が回る"ことを最優先
- 追加するほど破綻しないよう、Phase0〜5の思想に沿って改善する

---

## 2. 優先度の定義

| 優先度 | 定義 |
|--------|------|
| **P0** | 放置すると運用が止まる／事故が起きる／信頼が崩れる |
| **P1** | 運用が重い／不満が溜まるが回避策はある |
| **P2** | 便利になる／見栄え向上／将来の投資 |

---

## 3. 改善バックログ（機能別）

### 3.1 データ品質・運用（P0）

#### P0-01：設定不備の検知と可視化

| 項目 | 内容 |
|------|------|
| 検知対象 | URL未設定、REF参照切れ、アセット未登録、重複ID、manual衝突など |
| 表示 | 編集者に「要修正一覧」を出す |

**受け入れ条件**
- 編集者が"どこが壊れているか"を1画面で把握できる

---

#### P0-02：保存失敗時の安全策

| 項目 | 内容 |
|------|------|
| 巻き戻し | Sheets更新失敗時に、UI側が状態を巻き戻す |
| 整合性 | 監査ログ書き込み失敗も含めて整合性を担保 |

**受け入れ条件**
- 「保存したつもり」が起きない

---

#### P0-03：監査ログの閲覧UI（最低限）

| 項目 | 内容 |
|------|------|
| 一覧表示 | 監査ログを管理画面で一覧できる |
| 追跡 | "誰が何を変えたか"をすぐ追える |

**受け入れ条件**
- 事故時に原因追跡できる

---

### 3.2 編集体験（P0〜P1）

#### P0-04：衝突防止（manual/編集時）

| 項目 | 内容 |
|------|------|
| 視覚化 | ドラッグ/リサイズで衝突する場合は置けない（赤表示など） |
| チェック | 保存前に必ず整合性チェック |

**受け入れ条件**
- 保存後に重なりが発生しない

---

#### P1-01：Undo（取り消し）/ Redo（やり直し）

| 項目 | 内容 |
|------|------|
| 範囲 | 編集セッション内で最低限のUndo |
| 目的 | "うっかり"を救う |

**受け入れ条件**
- 編集ミスが致命傷にならない

---

#### P1-02：スナップと微調整の改善

| 項目 | 内容 |
|------|------|
| 罫線 | 表示ON/OFF |
| 吸着 | 近接配置時のスナップ |
| 制限 | 最小/最大サイズ制限の改善 |

**受け入れ条件**
- 編集がストレスなくできる

---

### 3.3 端末別最適化（P1）

#### P1-03：BP間の複製（PC→Tablet→Mobile）

| 項目 | 内容 |
|------|------|
| 対象 | 新規ページ追加時や新規ウィジェット追加時 |
| 動作 | PC配置をベースにTablet/Mobileへ自動生成 |
| 編集 | 生成後は各BPで編集可能 |

**受け入れ条件**
- 端末ごとの初期配置を作る手間が減る

---

#### P1-04：Mobile専用の縦並び最適化

| 項目 | 内容 |
|------|------|
| 配置 | Mobileは基本縦並び（1列寄り）になるよう優先配置 |
| embed | 縦方向を優先（読みやすさ） |

**受け入れ条件**
- モバイルで"読めない・押せない"が減る

---

### 3.4 埋め込み品質（P1〜P2）

#### P1-05：embedの常設操作ボタン

| 項目 | 内容 |
|------|------|
| 必須 | 「別タブで開く」を常設 |
| 任意 | 全画面表示（モーダル） |

**受け入れ条件**
- 埋め込みが微妙でも利用導線がある

---

#### P2-01：高さ自動調整（postMessage）

| 項目 | 内容 |
|------|------|
| 子側 | 埋め込み側（GAS/自作Web）で高さ通知 |
| 親側 | ポータルでiframe高さを更新 |
| 必須 | originチェック必須 |

**受け入れ条件**
- スクロールのストレスが減る

---

### 3.5 ナビゲーション・情報整理（P1〜P2）

#### P1-06：カテゴリ（セクション）表示の整備

| 項目 | 内容 |
|------|------|
| 方法 | divider/text/html を用いて「申請」「現場」「予約」などの区切りを強化 |
| 目的 | 画面が増えても迷わない |

**受け入れ条件**
- 目的のアプリが探しやすい

---

#### P2-02：検索（タイトル/説明/タグ）

| 項目 | 内容 |
|------|------|
| 対象 | ウィジェット数が増えたときのために検索を追加 |
| タイミング | MVPでは不要、増えてから導入 |

**受け入れ条件**
- 数十〜100件でも迷わない

---

### 3.6 管理（運用UI）（P0〜P1）

#### P0-05：ウィジェット追加・編集の管理UI（総務向け）

シートを直接触らずに以下ができる：

| 操作 | 内容 |
|------|------|
| 追加 | 新規ウィジェット作成 |
| 表示切替 | 表示/非表示 |
| 編集 | タイトル/URL更新 |
| アイコン | アイコン設定 |

**受け入れ条件**
- 総務が安全に運用できる

---

#### P1-07：棚卸ダッシュボード

| 項目 | 内容 |
|------|------|
| データ | review_cycle と updated_at を元に期限一覧 |
| 表示 | ownerごとの担当が見える |

**受け入れ条件**
- 放置で腐らない

---

### 3.7 パフォーマンス（P1）

#### P1-08：configキャッシュ最適化

| 項目 | 内容 |
|------|------|
| TTL | TTLキャッシュ |
| 無効化 | 編集保存後の即時キャッシュ無効化 |
| 目標 | 大きい設定でも表示が遅くならない |

**受け入れ条件**
- 体感が軽い

## 5. リリース後の回し方（運用手順）

### 5.1 フィードバック収集（最小）

編集者（あなた/総務）から以下を集める：
- 「困った点」
- 「壊れた点」
- 「追加したいウィジェット」

### 5.2 改善の優先順位付け

- P0→P1→P2 の順
- "見栄え"より "運用が止まらない"を優先

---

## 6. Phase 9 完了条件（Definition of Done）

- 改善項目が P0/P1/P2 に分類されている
- v0リリース後に「次に何をやるか」が迷わない
