# Phase 7：MVP定義と拡張ロードマップ

（1年 / 3年 / 5年スケールで進化し続ける設計）

## 1. このフェーズの目的

本フェーズの目的は、
「今すぐ動く最小実用（MVP）」を明確化しつつ、
**1年・3年・5年と進化できる拡張計画**を段階的に定義すること。

- MVPで"白いキャンバス"として成立させる
- 次に「運用が回る」状態へ
- 最後に「組織規模でも破綻しない」状態へ拡張する

---

## 2. MVP（v0）定義：最初に必ず実現する範囲

### 2.1 MVPのゴール

- 全社共通の `home` ページが表示できる
- 白いキャンバスにウィジェットを配置できる
- PC / Tablet / Mobile の見え方を切り替えて確認できる
- 編集者のみ配置を変更して保存できる
- embedは失敗してもリンクで開ける（フォールバック）

### 2.2 MVPで実装する機能（必須）

#### (A) データ駆動表示

- Sheetsから以下を読み取り、画面を生成する

| シート | 内容 |
|--------|------|
| 01_ページ | ページ定義 |
| 02_ウィジェット | 部品台帳 |
| 03_レイアウト | 配置定義 |
| 04_アセット | 画像・アイコン |
| 06_HTML本文 | markdown/html |

- visible=FALSE は描画しない

#### (B) ウィジェット種別の表示（最低限）

| type | 表示 |
|------|------|
| link | カード表示＋クリックで遷移（same_tab/new_tab） |
| embed | iframe表示＋「別タブで開く」導線、埋め込み不可はフォールバック |
| image | 画像表示（ヘッダー含む） |
| pdf | リンク表示（プレビューは任意） |
| sheet | リンク表示（埋め込みは任意） |
| html | markdown表示（安全運用） |

#### (C) レイアウト

- manual（x/y指定）を優先
- autoはPhase3の探索で配置
- 端末別（PC/TABLET/MOBILE）に配置が切り替わる

#### (D) 編集モード（Editorのみ）

| 機能 | 内容 |
|------|------|
| 編集モードON/OFF | 切り替え |
| ドラッグ移動 | グリッドスナップ |
| リサイズ | w/h変更、グリッド単位 |
| 保存 | ページ単位、03_レイアウトの更新、auto配置の確定座標も保存（推奨） |

#### (E) 権限・監査（最低限）

- Googleログイン必須
- Editorのみ編集画面へアクセス可能
- 保存時に監査ログ（timestamp, actor, target, before, after）を記録
  - 保存先はスプレッドシートのログシートでも可

### 2.3 MVPで"やらないこと"

- 個人ごとのダッシュボード
- 同時編集ロック
- 完全WYSIWYGなコンテンツ編集
- 高さ自動調整（postMessage）
- 高度な検索・タグ・おすすめ

## 3. v1（〜半年〜1年）：運用が回る状態へ

### 3.1 目標

- "作ったけど放置される"を防ぐ
- 総務が安全に扱える運用UIを整える
- ページ増加（部署別）の導線を実用化する

### 3.2 追加する機能候補

| 機能 | 内容 |
|------|------|
| ページ管理UI | 追加/並び替え/非表示、01_ページ をUIから操作 |
| ウィジェット管理UI | 追加/編集/非表示、02_ウィジェット をUIから操作 |
| 棚卸ダッシュボード | review_cycle に基づく期限一覧 |
| エラー可視化 | URL未設定、埋め込み不可、衝突など |
| PDF/Sheet埋め込み改善 | 可能な範囲で |

### 3.3 受け入れ条件（v1）

- 総務が "シートを直接触らず" に運用できる（理想）
- リンク/アプリが増えても破綻しない
- 棚卸が月次で回る

---

## 4. v2（〜2〜3年）：部署別ページ・情報整理・品質向上

### 4.1 目標

- 部署ごとに"必要なものだけ"見せる
- 量が増えても探せる・迷わない
- 埋め込みの体験品質を上げる

### 4.2 追加する機能候補

| 機能 | 内容 |
|------|------|
| 部署別ページ | 01_ページ に部署ページ追加、02_ウィジェット.audience / department を活用 |
| ナビゲーション強化 | サイドバー、カテゴリ、セクション（divider活用） |
| 検索（最低限） | タイトル/説明/タグでフィルタ |
| 埋め込み品質改善 | /embedビュー標準化、postMessageで高さ自動調整（任意） |
| 競合対策（軽量） | 保存時の更新検知、警告表示 |

### 4.3 受け入れ条件（v2）

- 部署別ページがスムーズに増やせる
- ウィジェットが数十〜100件でも破綻しない
- 埋め込みのUXが改善され「ポータル内で完結」感が増す

---

## 5. v3（〜4〜5年）：組織スケール・個人最適化・ガバナンス強化

### 5.1 目標

- 大規模運用（多数ページ/多数編集者/多数ウィジェット）に耐える
- 個人最適化も可能にする（必要な場合）
- 監査・復旧・統制を強化

### 5.2 追加する機能候補

| 機能 | 内容 |
|------|------|
| 個人/チーム別ビュー | 同じページでもユーザー属性で表示を変える |
| 変更承認フロー | 申請→承認→反映（総務向け） |
| ロールバックUI | 監査ログから復旧 |
| 同時編集ロック | ページ単位ロック |
| 外部DB移行 | Sheetsは維持しつつ、拡張データのみDBへ（必要時） |

### 5.3 受け入れ条件（v3）

- 変更が多くても事故らない
- 復旧が容易
- 組織統制の要件を満たせる

---

## 6. 段階移行の原則（絶対）

```
v0（MVP）    → 機能より土台
    ↓
v1（〜1年）  → 運用の勝ち筋を確立
    ↓
v2（〜3年）  → 便利さを追加
    ↓
v3（〜5年）  → 組織スケール対応
```

- 仕様（シート構造）を壊さない
  - 列は追加OK、意味変更は禁止

---

## 7. MVP（v0）受け入れチェックリスト

| チェック | 項目 |
|----------|------|
| [ ] | homeページが表示される |
| [ ] | PC/Tablet/Mobileプレビュー切替ができる |
| [ ] | link/embed/image/pdf/sheet/html が表示できる |
| [ ] | manual/auto配置が機能し崩れない |
| [ ] | 編集者だけがドラッグ/リサイズできる |
| [ ] | 保存すると次回も同じ配置になる |
| [ ] | 監査ログが残る |
| [ ] | 埋め込み不可でもリンクで開ける |

## 8. バージョン別サマリー

| バージョン | 期間 | テーマ | 主要機能 |
|-----------|------|--------|---------|
| v0（MVP） | 初期 | 土台構築 | 閲覧/編集/保存/監査ログ |
| v1 | 〜1年 | 運用安定 | ページ管理UI/棚卸/エラー可視化 |
| v2 | 〜3年 | 情報整理 | 部署別ページ/検索/埋め込み改善 |

## 9. 次アクション（推奨）

1. まず v0 を実装し、実運用で「必要な埋め込み」を絞る
2. その結果を基に v1（運用UI・棚卸）へ進む

---

- MVP（v0）の実装範囲が明確
- v1〜v3の拡張方針が段階的に定義されている
- 受け入れチェックリストが用意されている
- 「やらないこと」が明示されている
