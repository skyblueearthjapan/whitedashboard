# Phase 4：埋め込み仕様（AppSheet / GAS / 自作Web）

（iframe・フォールバック・/embed設計・表示品質）

## 1. このフェーズの目的

本フェーズの目的は、社内ポータル上で「アプリ画面が見えている」状態を実現するために、
**埋め込み（embed）ウィジェットの仕様・制約・フォールバック・推奨実装パターン**を明確化すること。

- embedの基本方式は `iframe` とする
- 埋め込み不可ケースを前提に、必ずフォールバック（link）を用意する
- AppSheet / GAS Webアプリ / 自作Web を混在させても破綻しない設計にする

---

## 2. 対象（前提）

主に埋め込みたい対象は自作アプリ：

| 対象 | 説明 |
|------|------|
| AppSheet | Google提供のノーコードアプリ |
| Google Apps Script | GAS Webアプリ |
| 自作Web | Next.js/SPA/社内Web等 |

※ 画像、PDF、スプレッドシート等は別typeで扱う（Phase2参照）

---

## 3. embedウィジェットの定義（データ連携）

### 3.1 該当データ

| 列 | 値 |
|----|-----|
| 02_ウィジェット.type | `embed` |
| 02_ウィジェット.url_or_ref | 埋め込み対象URL |
| 02_ウィジェット.embed_mode | `iframe` / `link_fallback` |

### 3.2 描画方針（必須）

| embed_mode | 動作 |
|------------|------|
| iframe | `iframe src = url_or_ref` で埋め込み |
| link_fallback | まず埋め込みを試みる（任意）、失敗/禁止/エラー時は linkカードに切替 |

※ 実装簡略のため、初期は「embed_mode=link_fallback」の場合は常にリンク表示でもよい
（ただし将来、埋め込み成功時だけiframeにする拡張余地を残す）

---

## 4. 埋め込みUI要件（UX）

### 4.1 共通の見た目（推奨）

embedウィジェットは以下の共通要素を持つ：

```
┌─────────────────────────────────┐
│ [icon] タイトル     [別タブ] [全画面] │  ← ヘッダー行
├─────────────────────────────────┤
│                                 │
│         iframe領域              │  ← 本体
│                                 │
└─────────────────────────────────┘
```

- ヘッダー行（最小）
  - アイコン（任意）
  - タイトル（必須）
  - 操作ボタン（推奨）
    - 「別タブで開く」
    - （任意）「全画面」
- 本体：iframe領域

### 4.2 リサイズとの関係

- embedは `03_レイアウト.w/h` に応じて表示枠が変わる
- 埋め込み側アプリは **レスポンシブに追従**することが望ましい
  （最低限：横幅が狭い時に壊れない）

### 4.3 スクロール方針

- 基本：iframe内スクロールを許容（`scrolling=auto`相当）
- 可能なら：埋め込み側アプリで高さ自動調整（後述）

※ 初期は必須ではない

---

## 5. セキュリティ・ブラウザ制約（必須理解）

埋め込みが失敗する主因は以下：

| 原因 | 説明 |
|------|------|
| X-Frame-Options | `DENY` / `SAMEORIGIN` 設定 |
| Content-Security-Policy | `frame-ancestors` 制限 |
| 認証方式 | SSO・CookieのSameSite制約等 |
| 外部サービス | iframe禁止ポリシー |

このため、**埋め込みできないケースを前提**に必ずフォールバックを実装する。

---

## 6. 対象別の推奨方針

### 6.1 AppSheet

#### 6.1.1 原則方針（重要）

- AppSheetは **原則「link」運用**を基本とする（安定性最優先）
- embedは「できたらやる」扱い（環境/設定に左右されやすい）

#### 6.1.2 推奨仕様

| 設定 | 値 |
|------|-----|
| 02_ウィジェット.type | `link`（基本） |
| embedが必要な場合 | type=`embed` + embed_mode=`link_fallback` |

※ 失敗時は常にリンクへフォールバック

---

### 6.2 GAS（Google Apps Script Webアプリ）

#### 6.2.1 方針

- 自作なので **埋め込み適性が高い**
- "埋め込み専用ビュー"を用意して埋め込み品質を上げる

#### 6.2.2 /embed ビュー（推奨）

GAS Webアプリは以下の2つの表示モードを用意する：

| モード | URL例 | 特徴 |
|--------|-------|------|
| 通常モード | `/` | ヘッダー・メニューあり、単体利用向き |
| 埋め込みモード | `/embed` | ヘッダー最小化 or なし、余白を小さく、ポータル内配置前提 |

※ URLの表現はGASのルーティング都合で変わってもよい（クエリ `?mode=embed` でも可）

---

### 6.3 自作Webアプリ（通常のコード）

#### 6.3.1 方針

- embed適性が最も高い
- /embedモード設計を標準とする

#### 6.3.2 推奨要件（埋め込み側アプリ）

| 要件 | 内容 |
|------|------|
| 埋め込みモード | `?embed=1` 等でナビ・フッター省略、余白最小 |
| レスポンシブ | 横幅が狭いときの崩れ防止 |
| 高さ連携（任意） | postMessageで高さを親に通知 |

---

## 7. 高さの自動調整（任意・将来拡張）

初期は「iframe内スクロール」で成立する。
より快適にする場合は以下を導入する：

### 7.1 postMessage 方式（推奨）

- 埋め込み側アプリが自分の高さを計算し、親へ通知
- 親（ポータル）がiframeの高さを調整する

```javascript
// 子（埋め込みアプリ側）
window.parent.postMessage({type: "HEIGHT", height: 980}, "https://portal.example.com")

// 親（ポータル側）
window.addEventListener("message", (event) => {
  if (event.origin !== "https://app.example.com") return
  if (event.data.type === "HEIGHT") {
    iframe.style.height = event.data.height + "px"
  }
})
```

※ セキュリティ上、originチェックは必須（`*`は本番禁止）

### 7.2 運用方針

- 初期MVPでは未導入でもよい
- ただし将来導入できるよう、embed枠の実装は拡張可能にしておく

---

## 8. フォールバック仕様（絶対）

埋め込みできない場合に備え、必ず次のフォールバックを用意する：

| 項目 | 内容 |
|------|------|
| 代替表示 | linkカード（タイトル＋アイコン＋「開く」） |
| 閲覧者向けメッセージ | 「このコンテンツは別タブで開きます」 |
| 編集者向けメッセージ | 「X-Frame-Optionsにより埋め込み不可」等の詳細 |

---

## 9. エラー状態の扱い

### 9.1 URL不正

| 対象 | 表示 |
|------|------|
| 閲覧者 | カード表示（設定未完了）または非表示 |
| 編集者 | 警告（URL未設定） |

### 9.2 認証エラー

- iframe内でログイン画面になるケースを想定
- 必要なら「別タブで開く」導線を常時表示

### 9.3 タイムアウト/表示失敗

- iframeのロード失敗は検知が難しい
- 初期は「フォールバックボタン常設」でUX担保する
