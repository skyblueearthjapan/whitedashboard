# Phase 2：UI / UX 仕様

（閲覧体験・編集体験・端末別プレビュー）

## 1. このフェーズの目的

本フェーズの目的は、
**「白いキャンバス型ポータル」をユーザーがどう見て、編集者がどう編集するか**を定義し、
実装者が迷わず画面と操作を作れる状態にすることである。

- データ仕様（Phase1）に基づき、UIがどう生成されるかを明確化する
- "ホワイトボード"らしさ（配置・リサイズ・ページ追加）を体験として固定する
- PC / タブレット / スマホ での見え方と編集の仕方を定義する

---

## 2. 画面（ページ）一覧

### 2.1 画面一覧（最小構成）

| パス | 説明 | 対象 |
|------|------|------|
| `/` または `/home` | ポータル表示（閲覧モード） | 全社員 |
| `/page/{page_id}` | ページ表示（閲覧モード） | 全社員 |
| `/admin` | 管理（編集）モード入口 | 編集者のみ |
| `/admin/page/{page_id}` | 該当ページ編集 | 編集者のみ |

※ URL設計は実装側に委ねるが、上記の概念は必須。

---

## 3. モード設計（閲覧 / 編集）

### 3.1 閲覧モード（Viewer）

全社員が通常利用する状態。

**できること：**
- ページ切替（タブ/サイドメニュー等）
- ウィジェット閲覧
- linkウィジェットのクリックで遷移
- embedウィジェット内の操作（可能な範囲）

**できないこと：**
- ウィジェットの移動/リサイズ
- ウィジェット追加/削除
- 配置変更の保存

### 3.2 編集モード（Editor）

編集権限者（本人＋総務一部）のみ。

閲覧モードのすべてに加えて、以下が可能：
- ウィジェットの移動（ドラッグ）
- ウィジェットのリサイズ（グリッド単位）
- 端末別プレビュー切替（PC/Tablet/Mobile）
- 変更の保存（スプレッドシートへ反映）
- ページ追加・ページ名変更（スプレッドシート定義反映）

---

## 4. ナビゲーション（ページ切替）

### 4.1 ページ切替UI

- 01_ページ に定義された page_id / page_title を表示する
- 表示順は 01_ページ.表示順 に従う
- 初期は `home` を必ず表示する
- 将来、部署ページを増やしても同じUIで対応できること

### 4.2 ページ追加体験（編集者）

- 編集モードで「＋ページ追加」相当の導線を提供する
- 入力項目：
  - page_id（英数字推奨、ユニーク）
  - page_title（表示名）
  - 初期レイアウト（auto推奨）
- 追加後は当該ページへ遷移し編集可能

※ 内部的には 01_ページ への行追加に対応する。

---

## 5. キャンバス（ホワイトボード）UI仕様

### 5.1 キャンバスの基本

- ページ背景色：01_ページ.背景色
- ヘッダー（任意）：01_ページ.ヘッダーアセットID に対応する画像を表示
- グリッド：
  - PC/Tablet/Mobile で列数が変わる（01_ページ.列数_*）
  - 行高さ：01_ページ.行高さ(px)
  - 余白：01_ページ.余白(px)
- "無限キャンバス"は必須要件ではない
  → 初期は縦スクロール可能なキャンバス（十分な高さ）でよい

### 5.2 グリッド基準（重要）

- 配置はピクセル自由配置ではなく **グリッド単位**で行う
- ウィジェットは必ずグリッドにスナップする
- 最小サイズ（例）：
  - w>=1, h>=1
- 編集時のリサイズもグリッド単位で行う

---

## 6. ウィジェット共通UI（外観と操作）

### 6.1 共通表示（基本）

ウィジェットは以下の基本要素を持つ（種別によって省略可）：
- タイトル（02_ウィジェット.タイトル）
- アイコン（02_ウィジェット.アイコンアセットID）
- 本体（種別ごとに異なる）
- （任意）説明文：将来拡張。初期は省略可

### 6.2 共通操作（閲覧）

- hover（PC）でハイライト（見た目向上）
- クリック/タップ動作は種別に従う

### 6.3 共通操作（編集）

- ドラッグ移動：ウィジェットを掴んで移動できる
- リサイズ：右下等のハンドルで拡縮（w/h変更）
- 選択状態：
  - 選択中は枠線・ハンドルを表示
  - 選択解除で通常表示

### 6.4 編集ガード（必須）

- 閲覧モードではドラッグ/リサイズ操作を無効化
- 編集モードでのみハンドル表示

## 7. 種別ごとの描画と挙動（Widget Type）

### 7.1 link（リンク/ボタン/カード）

| 項目 | 仕様 |
|------|------|
| 表示 | カード型（推奨）- タイトル＋アイコン |
| クリック | 02_ウィジェット.開き方 に従う |
| same_tab | 同一タブ遷移 |
| new_tab | 別タブで開く |
| URL | 02_ウィジェット.URL/参照 の URL を使用 |

### 7.2 embed（埋め込み）

| 項目 | 仕様 |
|------|------|
| 基本 | iframeで埋め込む |
| URL | 02_ウィジェット.URL/参照 |
| iframe | iframe表示 |
| link_fallback | 埋め込み不可時は link 相当のカードにフォールバック |

※ 推奨："ダッシュボード的に見たいもの"のみembedする（全部を埋め込まない）

### 7.3 image（画像）

| 項目 | 仕様 |
|------|------|
| URL/参照 | URL または `REF:ASSET_xxx`（04_アセット参照） |
| 表示 | 領域にフィット（切り抜き/余白は実装側判断） |

### 7.4 pdf（PDF）

| 項目 | 仕様 |
|------|------|
| 表示 | サムネ/プレビュー（可能な範囲） |
| クリック | 閲覧（同一タブor別タブは実装判断） |
| URL | DriveプレビューURL等を想定 |

### 7.5 sheet（Googleスプレッドシート）

| 項目 | 仕様 |
|------|------|
| 表示 | 埋め込み表示（可能なら） |
| フォールバック | 難しければ link フォールバック |
| URL | 該当シートURL |

### 7.6 html / text（本文）

| 項目 | 仕様 |
|------|------|
| html | 02_ウィジェット.URL/参照 が `REF:HTML_xxx` → 06_HTML本文 を参照して本文を表示 |
| format | markdown を基本（安全・運用容易） |
| text | 初期は html（markdown）で代替してもよい |

### 7.7 divider（区切り）

| 項目 | 仕様 |
|------|------|
| 表示 | 区切り線、セクション見出し等 |
| 用途 | 将来の"ヘッダーを増やす"の一部として利用可能 |

## 8. 端末別プレビュー（PC / Tablet / Mobile）

### 8.1 要件

編集者は、編集画面内で
**PC / Tablet / Mobile の見え方を切り替えて確認できる**こと。

### 8.2 UI案（必須要件の表現）

- 画面上部に「PC / Tablet / Mobile」切替ボタン
- 切替により、以下が変化する：
  - グリッド列数
  - レイアウト（03_レイアウト.bp）
  - ウィジェットの配置・サイズ

### 8.3 編集の振る舞い

- 現在選択中のBPに対して編集内容を反映する
  - 例：Mobileで並べ替えたら、Mobileの 03_レイアウト 行が更新される
- 他BPへ切り替えると、そのBPの配置を表示

---

## 9. 変更の保存と同期

### 9.1 保存単位

- ページ単位で保存（推奨）
- 保存対象：
  - 03_レイアウト（x,y,w,h,auto,pinned,z_index）
  - 必要に応じて 01_ページ / 02_ウィジェット の編集も

### 9.2 保存体験

- 編集後、「保存」ボタンで確定
- 保存中はローディング表示
- 保存成功/失敗のトースト表示

### 9.3 競合（同時編集）

- 初期は「同時編集は想定しない」でも良い
- 将来拡張でロック/競合検出を導入可能な余地を残す

---

## 10. エラー/フォールバック（UX要件）

| 状況 | 対応 |
|------|------|
| URLが空/無効 | ウィジェット枠内に「設定未完了」表示（編集者のみ詳細表示） |
| 埋め込み不可 | link_fallback へ |
| 権限不足 | 閲覧者には一般的なエラー表示、編集者には原因を表示 |

---

## 11. Phase 2 完了条件（Definition of Done）

- 閲覧モード/編集モードの操作が明文化されている
- ウィジェット種別ごとの見た目と挙動が定義されている
- 端末別プレビューとBP別編集の仕様が確定している
- 実装者がこのドキュメントだけで画面実装に着手できる
