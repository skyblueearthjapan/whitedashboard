# Phase 6：実装方針（技術構成 / データ取得更新 / モジュール分割）

（Spreadsheet駆動ポータルの実装設計）

## 1. このフェーズの目的

本フェーズの目的は、Phase0〜5で定義した仕様を実装へ落とすために、
**技術スタック・構成・データ連携方式・責務分割・ディレクトリ/モジュール設計**を明確化し、
コーディングエージェントが迷わずタスク分解して実装できる状態にすること。

---

## 2. システム全体像（論理構成）

本システムは大きく以下で構成される。

```
┌─────────────────────────────────────────────────────────────┐
│                    フロントエンド（ポータルUI）                │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────────────────┐ │
│  │ 閲覧モード   │ │ 編集モード   │ │ 端末別プレビュー        │ │
│  │             │ │(Editorのみ) │ │ (PC/Tablet/Mobile)     │ │
│  └─────────────┘ └─────────────┘ └─────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
                              ↓↑ API
┌─────────────────────────────────────────────────────────────┐
│                    バックエンド（API）                       │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐           │
│  │ 読み取りAPI  │ │ 書き込みAPI  │ │ 権限チェック │           │
│  └─────────────┘ └─────────────┘ └─────────────┘           │
└─────────────────────────────────────────────────────────────┘
                              ↓↑ Sheets API
┌─────────────────────────────────────────────────────────────┐
│              Google スプレッドシート（設計DB）                │
│  01_ページ / 02_ウィジェット / 03_レイアウト / 監査ログ       │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 フロントエンド（ポータルUI）

- 閲覧モード
- 編集モード（Editorのみ）
- 端末別プレビュー（PC/Tablet/Mobile）
- レイアウト表示（manual/auto）

### 2.2 バックエンド（設定データ取得/更新API）

- Google Sheets（設計DB）の読み取り
- 編集操作の書き込み（保存）
- 監査ログの追記
- 編集者判定（権限）

### 2.3 Google スプレッドシート（設計DB）

- 01_ページ、02_ウィジェット、03_レイアウト…（テンプレに準拠）
- （追加）監査ログシート（Phase5）

## 3. 技術スタック（推奨：変更可）

### 3.1 推奨スタック（例）

| レイヤー | 推奨技術 |
|---------|---------|
| フロント | Next.js（React）または同等のSPA/SSRフレームワーク |
| API | Next.js API Routes / Cloud Run / Apps Script Web API のいずれか |
| 認証 | Google Workspace（OAuth / IAP / SSOいずれか） |
| Sheetsアクセス | Google Sheets API（サービスアカウント or OAuth） |

※ 組織の制約に合わせて選定すること。
ただし「ブラウザから直接Sheets更新」は避け、**サーバ側経由**を推奨。

## 4. データ連携方式（読み取り）

### 4.1 読み取りの基本戦略

- 画面表示のたびにSheetsへ取りに行くと遅い場合があるため、
  **キャッシュ戦略**を用意する（最小でもメモリキャッシュ）
- 読み取りは基本「ページ単位」または「全体一括」で取得

### 4.2 推奨エンドポイント（例）

| エンドポイント | 説明 |
|---------------|------|
| `GET /api/config` | 01_ページ / 02_ウィジェット / 03_レイアウト / 04_アセット / 06_HTML本文 をまとめて返す |
| `GET /api/config?page_id=home` | ページに必要な分だけ返す（軽量化） |

### 4.3 キャッシュ（推奨）

- TTLキャッシュ（例：30〜120秒）
- 編集保存後はキャッシュを即時無効化

---

## 5. データ連携方式（書き込み：保存）

### 5.1 書き込みは編集者のみ

| エンドポイント | 説明 |
|---------------|------|
| `POST /api/save-layout` | 03_レイアウトの更新（x,y,w,h,auto,pinned,z_index）、監査ログも追記（Phase5） |

### 5.2 保存単位（推奨）

- ページ単位で保存
  - `page_id` と `bp` をキーに該当行を更新
- 更新方式
  - 既存行の update
  - 新規行の append
  - 削除は原則ソフトデリート（visible=FALSE or 該当行削除は慎重に）

### 5.3 監査ログの追記（必須）

- `POST /api/save-layout` 実行時に
  - before/after をログシートへ追加
- ログ書き込みが失敗した場合は保存も失敗扱い（推奨）

---

## 6. 認証・認可（実装方針）

### 6.1 認証

- Googleログイン必須（方式は環境に合わせる）
- APIはログインユーザー情報（メール）を取得できること

### 6.2 認可（Editor判定）

| 方式 | 内容 | 推奨 |
|------|------|------|
| 初期 | 編集者メールのホワイトリスト（環境変数） | 初期可 |
| 長期 | シートで管理（例：07_権限シート） | ✅ 推奨 |

- 認可はAPI側でも必ずチェックし、UI側だけに依存しない

---

## 7. レイアウトエンジン（責務分割）

### 7.1 レイアウト計算（Phase3）

```typescript
LayoutEngine.compute(page_id, bp, config) → ComputedLayout
```

| 入力 | 説明 |
|------|------|
| cols | ページ定義 |
| widgets | 表示対象 |
| layoutRows | manual/auto定義 |

| 出力 | 説明 |
|------|------|
| rectリスト | 画面描画用（x,y,w,h + widget参照） |
| 警告 | manual衝突、欠損など |

### 7.2 保存との関係

- 編集者が「保存」した時に
  - auto配置の確定座標も含めて03_レイアウトへ書き戻す（推奨）

## 11. デプロイ方針（例）

環境制約により変わるが、最低限以下を満たすこと。

- 社内ユーザーのみアクセス可能
- Google認証が機能する
- Sheets API の認証情報（サービスアカウント等）が安全に管理される

### デプロイ例

| 構成 | 説明 |
|------|------|
| Vercel + Google OAuth | 閲覧/編集 |
| Cloud Run + IAP + サービスアカウント | エンタープライズ向け |
| Apps Script Web API + 静的ホスティング | 小規模向け（UI規模次第） |

---

## 12. ログ・監視（最小）

以下のイベントを記録・監視する：

- APIエラー（Sheets read/write失敗）
- 認可失敗（403）
- manual衝突などのデータ不整合
- embedのフォールバック発生（参考）

## 13. 実装タスク分解（MVP）

Phase6の結論として、MVP実装は以下の順で進める。

| 順序 | タスク |
|------|--------|
| 1 | config読み取り（Sheets→内部モデル） |
| 2 | 閲覧モードでページ描画（Canvas + WidgetRenderer） |
| 3 | BP切替（PC/Tablet/Mobile） |
| 4 | LayoutEngine（manual+auto配置） |
| 5 | 編集モード（ドラッグ/リサイズ） |
| 6 | 保存API（03_レイアウト更新） |
| 7 | 監査ログ追記（Phase5要件） |
| 8 | 権限（Editorのみ編集） |
